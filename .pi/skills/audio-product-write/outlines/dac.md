# DAC Review Outline

The canonical section structure for DAC reviews. Sections are mandatory unless the assessment genuinely has nothing to say on a topic.

Artwork placement is specified at the end of each section.

---

## 1. Preambles

```
Preambles
===

- In this review, I use the term "source" to denote a DAC+amp combo for brevity and convenience.
- Sources do not make sounds. Therefore, when I say sources "sound" a certain way, I talk about the change they make to my IEMs and earphones.
- I want my music to be crisp, clear, well-separated and form a 3D soundstage around my head. Sources that intensify those characteristics of my IEMs are considered "better".
- **This review is based on a review sample from [Provider] (Thank you!).** I have no affiliation with or financial interest in [Manufacturer].
- The unit retails for **[Price]**. Unaffiliated link: [URL]
```

Use "review sample from [Provider]" for tour/loan units, or "I purchased this unit on my own" for self-bought. For retail price, use the figure from the session file (or `[VERIFY]` if not confirmed).

---

## 2. General Information / Specs

A spec table plus 1–2 paragraphs on hardware architecture (DAC chip, amp topology, inputs, outputs, gain, power delivery). Reference the research file's confirmed specs. If the unit sits within a product family, a brief positioning note is appropriate (what it replaces or sits above/below).

DAC reviews sometimes include a brief walkthrough of the manufacturer's product lineup if the unit is positioned within a family.

**Artwork:** One or more `generic` slide showing the front and rear panels.

~250–400 words.

---

## 3. Non-sound Aspects

Build quality, physical design, controls (volume, input switching, gain), compatibility (OS support, USB-C quirks), idle battery drain for portable units. Reference real-world observations from the session file.

**Artwork:** One or more `generic` slide showing the unit in context (on a desk, in hand). Caption: one-line factual description.

~200–300 words.

---

## 4. Sound Performance

Open with a **Test setup** block listing the IEMs used, cables, ear tips, and listening volume level. Then:

- **Tonality and Technical Performance** (~200–400 words): perceived tonality, how it changes the IEM, dynamic behaviour, staging character, resolution character. Reference tracks from `/test-tracks`.
- **Driveability testing** (~200–400 words): test against a sequence of IEMs covering easy-to-drive, high-sensitivity / low-impedance, and difficult-to-drive. Describe what changes at each pairing.

Compare against the Apple USB-C dongle baseline throughout. The Apple dongle is the zero point — describe how this DAC changes the sound relative to it on the same IEM and same track.

**Artwork:** One or more `generic` slide showing the unit with an IEM and source cable. Caption: one-line factual description.

---

## 5. Selected Comparisons

One to three sources, each ~150–200 words. Common baselines: Apple dongle (2/5), a generic audiophile USB DAC from 2023 (3/5), a desktop DAC (4/5). If this DAC beats a desktop DAC, mark it 5/5.

**Artwork:** One or more `generic` slide per comparison source if available. Caption: "[Source name]."

---

## 6. Conclusions

```
Conclusions
===

<Gen's overall take, 1–3 paragraphs.>

**What I like about this device:**

- bullet
- bullet
- ...

**What could be improved:**

- bullet
- bullet
- ...

**Absolute Sonic Quality Rating: <score>/5 - <descriptor>**
```

Fill ratings from the session file's Final Assessment section or from Gen's verbal close. If neither is present, ask Gen before inventing numbers.

~200–300 words total (prose only; bullets and rating block are additional).

Artwork: summary slide at the end of the review.
